## What an agent needs to know first

- **Access is gated.** Every operation requires an enterprise OAuth 2.0 `client_credentials` token.
  appId/appKey are issued only after an enterprise developer application AND an application
  registration are approved at https://dev.3vjia.com/manage/my-app/developer. There is no self-serve key.
- **Failures are HTTP 200.** The gateway returns HTTP 200 for success, for a missing credential
  (`code: 100100002`) and for an unrouted path (`code: 100001012`). Branch on the body's `success`
  field, never on the status code.
- **There is no idempotency.** No idempotency key, dedupe parameter or replay guard exists on any of
  the 429 operations. A retried write is a real double-fire risk.
- **Everything is POST.** All 429 operations are `POST` with `Content-Type: application/json;charset=utf-8`;
  the verb lives in the path (`/api/v1/user/deleteBatch`). This is RPC over HTTP, not REST.
- **Documentation is Chinese-only.**
- **The provider publishes no OpenAPI.** It publishes a complete, anonymously readable documentation
  service instead. The OpenAPI in this repository is a mechanical transform of it and is marked derived.

## Authentication

- [Authentication profile](authentication/3vjia-technology-authentication.yml)
- Token endpoint: `POST https://graph.3vjia.com/oauth/token`,
  `Content-Type: application/x-www-form-urlencoded`, `grant_type=client_credentials`,
  `client_id=<appId>`, `client_secret=<appKey>`. Returns `{access_token, expires_in: 7200}`.
- **Only one token is valid at a time.** A new token invalidates the previous one, so the provider
  requires an enterprise-wide central token service rather than per-system fetches.
- Separate SSO: `https://sso.3vjia.com/JointLogin/Index`, MD5-signed redirect
  (`sign = MD5(userId + appId + time + appKey)`), ±5 minute clock tolerance.
